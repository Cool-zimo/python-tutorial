# 写给人看的文字

> 注释是那种「不会让程序运行得更快，但会让你三个月后的自己不至于崩溃」的东西。这一课讲它为什么重要，以及怎么写才不浪费。

## 注释长什么样

在代码里写一个 `#` 号，从它开始到这一行结束，Python 会**完全无视**：

```python
# 这行是注释，Python 看不见它
print("这行会被执行")   # 这里也是注释，写在一行代码的后面也行
```

运行上面的代码，只会输出「这行会被执行」。注释就像给代码贴的便利贴，只有人能看见。

## 那它有什么用？一个扎心的真相

先说结论：

> **代码被阅读的次数，远远多于被编写的次数。**

你写的每一行代码，自己会读好几遍（调试时），同事会读，未来的你会读。而三个月后的你，和现在的你几乎是两个人 —— 你会盯着自己写的代码想：「这写的是什么玩意儿？」

注释就是给那个"未来的你"留的线索。

### 一个没有注释的例子

```python
d = 30
t = 2.5
v = d / t
print(v)
```

能看懂吗？勉强。`v` 大概是速度。但 `d` 是距离还是天数？单位是米还是公里？

### 加上注释之后

```python
# 计算从家到公司的平均速度
d = 30      # 距离，单位：公里
t = 2.5     # 用时，单位：小时
v = d / t   # 速度 = 距离 / 时间
print(v)
```

代码一行没变，但现在是个人都能看懂了。

## 好注释 vs 坏注释

这是这一课真正想教你的东西。**不是多写就好，是写对地方。**

### ❌ 坏注释：复述代码

```python
print("你好")   # 打印"你好"
```

这行注释是废话。代码本身已经说了它在打印"你好"，注释只是重复了一遍，还多了一行要维护。

### ✅ 好注释：解释"为什么"

```python
# 这里必须用 0.1 而不是整数，因为上游接口只认浮点数
price = 0.1
```

**代码说明"做了什么"，注释说明"为什么这么做"。** "为什么"是代码里唯一写不出来的东西，才是注释该待的地方。

### 三种真正有用的注释

**1. 解释意图**

```python
# 先按时间排序，因为后面的去重逻辑依赖顺序
data.sort(key=lambda x: x["time"])
```

**2. 标记待办**

```python
# TODO: 这里以后要接入真实的支付接口，现在是假数据
```

`TODO` 是程序员之间约定俗成的标记，意思是「我知道这里不完整，以后回来补」。

**3. 临时禁用代码**

调试时你常想"先不跑这一行看看会怎样"，与其删掉，不如注释掉：

```python
print("这行要跑")
# print("这行先不跑，等会儿再说")
print("这行也要跑")
```

删掉的代码找不回来，注释掉的一键就能恢复。这是**最高频**的注释用法。

## 多行注释怎么做？

Python 没有专门的"多行注释"语法。两种做法：

**方法一：每行加 `#`（正规做法）**

```python
# 这个函数用来计算折扣后的价格
# 参数 price 是原价，rate 是折扣率（0.8 表示八折）
# 返回值保留两位小数
```

**方法二：三引号字符串（严格说不是注释，但效果类似）**

```python
"""
这个函数用来计算折扣后的价格
参数 price 是原价，rate 是折扣率
"""
```

三个引号包起来的叫**文档字符串（docstring）**，常写在函数/文件开头当说明。它技术上是个字符串，没赋值给任何变量时不影响程序，所以看起来像注释。

**初学阶段用方法一就够了**，简单、不会出错。

## 注释的两条铁律

1. **代码改了，注释必须跟着改。** 错误的注释比没有注释更害人 —— 它让你信以为真。
2. **能用好名字说清楚的，就不要写注释。** 比如把 `d` 改成 `distance_km`，比写注释「d 是距离」强一百倍。（下一章就讲变量命名）

下面这段代码本该输出三行，但后面两行被人注释掉了。

你的任务：**去掉多余的 `#`**，让三行文字全部输出。

```quiz
type: code

starter: |
  print("第一行：早上好")
  # print("第二行：中午好")
  # print("第三行：晚上好")
tests:
- assert "第二行：中午好" in __out
- assert "第三行：晚上好" in __out
hint: 把第 2 行和第 3 行最开头的 # 删掉，让它们重新变成真正的代码。第 1 行保持不变。
explain: 这就是注释最高频的用法 —— 临时禁用。调试时把怀疑有问题的行注释掉，能快速定位问题出在哪一段。熟练之后，这会成为你的肌肉记忆。
```

做完之后，试着反过来做一遍：在第 2 行前面加回 `#`，再运行看看。感受一下"注释掉一行"和"删掉一行"在调试时的区别 —— 前者可逆，后者不可逆。
